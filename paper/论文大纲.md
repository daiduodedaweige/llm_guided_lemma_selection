# 论文大纲：面向 RTL 形式化验证的高效归纳引理选择

> **拟题**：面向 RTL 形式化验证的大语言模型与证明反馈协同的高效归纳引理选择方法  
> **英文拟题**：LLM-Guided Cost-Efficient Inductive Lemma Selection for RTL Formal Verification  
> **方法名称**：LLM-GLS（LLM-Guided Lemma Selection）

**中心问题**：给定同一 RTL 设计、目标安全属性和固定候选引理池，如何在统一的选择与证明预算内，以更少的形式化查询和更短的含 LLM 开销的证明时间，找到足以完成归纳证明的引理组合？

**论文主线**：固定候选生成与验证条件 → 定义目标导向的组合选择问题 → 用 LLM 推荐非前缀组合 → 用可靠的形式化失败证据修复与过滤组合 → 以成本规则决定检查、再调用或 Houdini 回退 → 在三组实验中分别评估总体效果、候选池鲁棒性和核心设计的增量收益。所有证明结论以形式化后端为准。

## 摘要（实验完成后撰写）

- 背景与问题：RTL 安全属性的 1-Induction 常需辅助引理；固定排序的前缀搜索可能漏掉有效的非前缀组合，额外的 LLM 调用也可能抵消求解收益。
- 方法：概述语义协同选择、结构化证明反馈修复、安全的反例必要条件过滤、成本感知检查顺序与 Houdini 回退。
- 实验：说明固定候选池、统一 EBMC 后端和预算，以及与 Prefix Search、Classical Houdini 的比较。
- 结果与结论：待完成正式实验后填入实测的完成率、时间、查询量与适用边界；不预写优势结论。

## 1 引言

### 1.1 研究背景与动机

- 介绍 RTL 安全属性验证、BMC 与归纳证明的关系，以及目标属性本身不满足 1-Induction 时辅助引理的作用。
- 说明候选引理已有生成途径，但生成后的组合搜索仍消耗形式化查询和墙钟时间。
- 用“有效组合不是固定排序前缀”的简例引出目标导向、组合级选择的必要性。

### 1.2 研究问题与挑战

- **RQ1**：LLM 引导的选择能否在维持有竞争力的证明完成率时减少查询与证明时间，且收益覆盖模型推理开销？
- **RQ2**：候选池扩大、混入无关／冗余／非归纳候选时，方法是否仍有效？
- **RQ3**：组合级初始选择和结构化证明反馈各自是否带来可测量的增量收益？
- 挑战包括候选间联合归纳依赖、反例语义不完整、模型输出不可直接信任，以及查询与模型调用共享时间预算。

### 1.3 拟定贡献与文章结构

- 提出利用 RTL 状态关系、目标属性和候选语义联系的非前缀组合选择。
- 提出基于归纳失败义务的组合修复与安全过滤，并用统一预算规则管理检查、再调用和回退。
- 构建可审计的选择与验证框架，并计划在相同固定候选池和形式化后端上开展三组对照实验。
- 上述为**待实验支持的贡献主张**；成本回退的独立性能贡献只有在增加专门对照后才宣称。

## 2 背景、相关工作与问题定义

### 2.1 RTL 安全属性与归纳增强

- 定义转移系统 $T=(V,Init,Tr)$、目标属性 $p$、候选池 $C=\{\ell_1,\ldots,\ell_n\}$ 与选中子集 $S\subseteq C$。
- 定义 $Inv_S=p\land\bigwedge_{\ell\in S}\ell$；明确成功需要初始性 $Init\Rightarrow Inv_S$ 和归纳性 $Inv_S\land Tr\Rightarrow Inv_S'$ 均由后端证明。
- 区分真实可达反例、步骤反例与证明未决：BMC 无反例不构成证明；NO_PROOF_IN_POOL 也不等于目标属性不安全。

### 2.2 相关工作及本文定位

- 候选生成与 Large Lemma Miners：说明复用其生成思路，本文不把生成能力差异归因于选择算法。
- Prefix Search：按候选分类、排序后搜索前缀；比较其固定组合结构与本文的非前缀选择。
- Classical Houdini：迭代删除不满足归纳条件的候选；区分求固定池归纳子集与尽早证明指定属性。
- 讨论 H-Houdini、LLM 引导不变式推断等工作与本文的任务边界，避免把已有的分层或性质导向思想误作本文独创。

### 2.3 固定候选池上的优化目标

- 将任务固定为 $(D_i,p_i,C_i)$；各方法共享候选内容、ID、顺序、环境假设、SVA 语义和验证后端。
- 定义主要指标：统一预算内的 Solved Properties、包含 LLM 选择耗时的 Proof Time、Formal Queries；辅以 Solver Time、LLM Calls / Tokens 和最终引理数。
- 规定结果语义：PROVED 需完整证明；目标属性的真实可达反例须与归纳步骤反例区分；TIMEOUT、UNKNOWN、ERROR／缓存缺失单独记录。

## 3 LLM-GLS：证明反馈驱动的组合选择

### 3.1 总体架构

- 展示 Candidate Generator、LLM-Guided Selector、Formal Induction Checker、Cost-Aware Controller 的数据流；候选生成配置固定。
- 说明组合检查 `Check(S)` 的顺序：先初始性，后归纳步骤；每组均按相同语义检查，已验证且配置不变的结果可复用。

### 3.2 候选预处理与初始语义组合

- 冻结候选来源顺序、不可变 ID、原文／解析结果／内容哈希；仅做不改变语义的解析与去重。
- 初始 LLM 调用同时输出候选排序和最多 $m$ 个候选 ID 组合，以支持“推荐组合 vs 同次输出的排序前缀”对照。
- 校验 ID、去重、非空和最大规模 $K$；无效响应的重试、耗时及 tokens 均计费，LLM 不得在选择阶段新写引理。

### 3.3 形式化反馈、必要条件过滤与局部修复

- 区分初始性失败、目标属性步骤失败、辅助引理步骤失败；步骤反例可以同时违反多个后继义务。
- 仅在相同时钟、复位和 SVA 展开语义下对反例状态求值，使用 true／false／unknown 三值；无法可靠求值时不得据此剪枝或禁用候选。
- 说明安全过滤的必要条件：旧反例的源状态若仍满足新组合全部引理，则该反例仍否决该组合；只要存在 unknown 且无确定阻断者，就保留待查。
- 初始状态独立证实为假的候选可全局禁用；步骤失败不能据此全局禁用候选，因为它可能需要联合支持。
- LLM 根据失败义务修复组合；同时生成有限的本地修复（删除失败引理或加入可确定排除反例源状态的候选），去重后重新检查。

### 3.4 组合优先级与成本决策

- 先执行确定性过滤，再依已覆盖反例比例、提议顺序和预测验证耗时排列可行组合；明确该分数仅决定检查顺序，不是证明成功概率。
- 根据开发集先验和当前任务已发生的调用，估计不同组合规模的初始性／步骤查询耗时及 LLM 耗时；不使用测试任务未来结果校准。
- 在共同墙钟预算 $B$ 下，对候选检查、模型修复调用和 Houdini 回退实施准入；限制单次调用、选择阶段查询数与模型追加调用数，并为回退预留时间。
- 预留是策略阈值而非完成保证；所有预测、实际耗时、调用数和触发原因写入审计记录。

### 3.5 Houdini 回退、正确性边界与算法描述

- 回退基于**完整固定候选池**，仅排除已由初始状态证据或独立编译错误证实不可用的候选；不因 LLM 漏选、单次步骤失败或低分删除候选。
- 描述 Houdini 的初始性过滤、归纳不动点和目标属性最终检查；仅在相关查询完成、证据与语义一致时，讨论固定候选池内的条件性保障。
- 给出完整伪代码和一例非前缀组合的检查—反例—修复过程；强调最终 PROVED 必须有完整形式化证明。

## 4 框架实现与证据管理

### 4.1 固定候选池与运行流程

- 说明生成后接入 live non_agent 选择流程，沿用候选与评估 JSON 接口；原 agent 流程仅作生成侧参考。
- 交代候选 ID 映射、组合队列、预算控制、Houdini 控制与事件日志的实现；说明候选生成是各方法共用的前置阶段，选择阶段成本另行统计。

### 4.2 EBMC 检查适配

- 统一 EBMC 版本、1-Induction、目标 BMC 深度、时钟／复位及环境假设；记录原生查询状态和底层查询次数。
- 说明 EBMC 5.9 步骤 SAT 可能仅报告 INCONCLUSIVE：对可保守识别的单周期状态谓词，使用**额外计费**的一步查询与探针读取证实反例；时序或混合采样语义不明时返回 UNKNOWN。
- 额外一步查询及其反例不能替代原生归纳证明；缺乏可靠证据时只可保守回退。

### 4.3 可复现性与实现验证

- 保存候选池哈希、Prompt／模型版本与参数、种子、组合历史、反例求值、每次查询状态与耗时、回退原因、最终证明日志。
- 描述已有的离线单元测试与 EBMC 集成测试覆盖范围；正式论文须补充批量运行与实验复现记录。

## 5 实验设计与结果分析（待正式运行后填充结果）

### 5.1 数据集、基线与公平性设置

- **Dataset A**：计划使用 Large Lemma Miners 的 109 个 RTL/SVA 任务（78 个常规、31 个困难）；逐任务固定同一生成配置的候选池，正式运行前核查缓存覆盖、候选提取及跨运行去重。
- **Dataset B**：在已知有效核心组合上逐步增加无关、冗余或非归纳候选；20／50／100／200 条仅为待开发集调整的起始规模。
- 主外部基线为 Prefix Search（PS）与 Classical Houdini（CH），均使用同一候选池及统一形式化后端；不把跨设置 Virtual Best 当作单一配置结果。
- 按 RTL 设计家族区分开发任务与正式测试任务；模型、Prompt、推理参数、后端版本、机器资源、缓存口径和总预算预先冻结。
- 起始配置可采用单任务总预算 600 s、单次形式化查询 120 s、BMC 深度 30、至少 3 次重复；这些均需先在开发集校准，不是已验证的最优设置。

### 5.2 指标与统计呈现

- 主指标：Solved Properties、Proof Time、Formal Queries；辅助指标：Solver Time、LLM Calls / Tokens、Inference Time、Selected Lemmas。
- 固定池的 Proof Time 从选择开始，包含 LLM 推理、形式化检查及其他处理；候选生成是共用前置成本，不计入方法间的证明时间比较。
- 全体任务保留超时和未决状态，报告完成率、Cactus Plot 与时间分解；共同成功的任务再报告配对时间／查询差异和相对 CH 的加速比。

### 5.3 Experiment 1：证明有效性与效率（RQ1）

- 在 Dataset A 上比较 PS、CH 和 LLM-GLS 的完成率、证明时间及查询量。
- 在选择阶段分别报告 LLM 推理与形式化检查耗时，检验模型开销能否被节省的查询／求解时间抵消。
- **预留图表**：总览表、Cactus Plot、配对加速比图、选择阶段耗时分解图。

### 5.4 Experiment 2：候选规模与干扰鲁棒性（RQ2）

- 在 Dataset B 的相同核心组合上，仅改变干扰候选数量、类型和比例；三种方法逐设置共享同一候选池。
- 比较 Proof Time、Formal Queries、Solved Properties 与 LLM Inference Time 随规模的变化。
- **预留图表**：规模—证明时间曲线、规模—查询量曲线、按干扰类型分组的结果图。

### 5.5 Experiment 3：关键设计对照（RQ3）

- **组合选择对照**：用同一次 LLM 输出的推荐组合与相同排序构成的前缀进行比较；两组均不做反馈修复，并采用相同回退规则。
- **结构化反馈对照**：从相同初始组合出发，比较“失败义务＋相关候选 ID”与“仅告知成败后重试”；保持最大修复轮数、模型调用上限及回退规则一致。
- 报告全体任务完成率与成本、共同成功任务的配对差异，并如实统计因提前成功而产生的实际调用数差异。
- 修复轮数累计收益／成本曲线可作为补充，完整参数敏感性放附录；若要宣称动态回退本身有独立收益，再增设与开发集确定的固定回退策略的对照。

## 6 讨论与有效性威胁

### 6.1 方法适用范围

- 分析小候选池中 Houdini 可能已足够快、LLM 延迟可能抵消收益，以及非前缀组合在哪些任务上有价值。
- 区分固定候选池内的选择效率与在线生成—选择闭环；后者会改变候选池，不在本文主实验的因果归因范围内。

### 6.2 证据与测量边界

- 讨论 SVA 采样／时钟复位语义、反例求值 unknown、EBMC INCONCLUSIVE、工具或缓存故障对结论的影响。
- 讨论候选缓存覆盖、设计家族重叠、Prompt／模型随机性、重复运行离散程度和时间预算对外部有效性的影响。
- 区分证明未找到、池内无归纳增强、目标真实不安全三种结论，避免把超时或未决计作算法失败的证明。

## 7 结论与未来工作

- 回答 RQ1—RQ3，以正式实验数据概括适用条件、成本与局限，不超出证据宣称成功率或加速优势。
- 后续方向：更广泛的 RTL 设计与 SVA 类型、在线候选生成与选择闭环、在独立对照下评估动态回退策略。
